```bash
npm add @aedge-io/grugway@0.2.0
```

#### Trimming down

In an effort to actually simplify grugway, I've concluded that the initial
adapters module has to be removed. It's not fundamental adds more noise to the
whole library. Especially since the implementation is quite trivial, if you know
how `liftFallible` works. Therefore it was moved to the `examples` directory, to
demonstrate how lifting fallible functions composes with custom `Result`
constructors for more fine-grained control.

Also `trip` and `rise` methods have finally been removed, after they've been
deprecated a while back.

### Features

- feat(async): implement Promise parity without subclassing
  ([7adbbd1](https://github.com/aedge-io/grugway/commit/7adbbd110eeb860c0e5b6be4f9795ee6515c1161)
  by [@raphael-paier](https://github.com/raphael-paier))

#### More light weight `Task`

I've finally came around to implement a change, I've had already planned way
back: Full `Promise` compatibility without the performance penalties of
subclassing. Although I've never experienced any performance degradation, it
just kept stinging that the subclassing approach was wasteful by allocating more
Promises than necessary. This path has been initially chosen, because I've
tripped over libraries being (wrongfully) invariant over `PromiseLike` objects
and rely on `instanceof` checks.

But thanks to static initialization blocks, we can now simply wrap a
`Promise<Result<T, E>>`, implement the full `Promise` interface and still allow
for `instanceof` checks. All while reducing GC pressure and increasing
throughput significantly (2-6x according to the micro benchmarks).

```typescript
import { assert } from "@std/assert";
import { Task } from "@aedge-io/grugway";

const task = Task.succeed("hooray!");

assert(task instanceof Promise);
assert(task instanceof Task);
```

#### QoL

Very subtle, but it always bugged when, when simply wrapping an `Ok<T>`, the
static `Task.of` constructor would infer the error type as `unknown`. I've added
correct overloads now to alleviate this.

```typescript
import { Err, Ok, Task } from "@aedge-io/grugway";

const success = Task.of(Ok("hooray")); // now correctly inferred as `Task<string, never>`
const failure = Task.of(Err("boooo0m")); //now correctly inferred as `Task<never, string>`
```
